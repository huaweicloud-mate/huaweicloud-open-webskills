# 浏览器支持矩阵与分级策略

## 版本策略（L 含义）

L 代表 last（最近稳定版本）：

| 标记 | 含义 |
| --- | --- |
| L1 | 产品版本上线时最新的 1 个稳定浏览器版本 |
| L2 | 产品版本上线时最新的 2 个稳定浏览器版本 |
| L3 | 产品版本上线时最新的 3 个稳定浏览器版本 |

版本支持以「产品版本上线时点」为准，上线前需按当时最新稳定版本重新核对。

## 支持级别定义

| 级别 | 定义 | 要求 |
| --- | --- | --- |
| A 级 | 最高支持级别 | 充分利用 H5 和 CSS3 等技术，提供完全匹配高保真设计的视觉和交互效果，逐项测试 |
| B 级 | 有限支持级别 | 满足基本的样式、布局效果并能正常交互；不考虑因浏览器自身对 H5/CSS3 等新技术支持有限导致的视觉、交互差异 |
| C 级 | 不承诺支持 | 针对未知、零散的很少使用或已停止开发的浏览器；不承诺兼容，必要时提示升级浏览器 |

## 矩阵解读与执行

- PC 端以 Chrome 为开发主基准（L3/A）；Edge 同为 Chromium 内核、行为一致；Firefox 重点回归布局与动效细节。
- PC 端 Safari 为 B 级（L2）：保证基本样式、布局与交互可用，不做像素级还原承诺。
- Edge < 79（EdgeHTML 内核）与 IE 11 为 C 级：不承诺支持、不列入测试。
- 移动端 Safari（iOS）与微信内置浏览器（iOS 端为 WKWebView / Safari 内核）按 A 级处理，需重点回归。
- 微信内置浏览器通过 UA 包含 `MicroMessenger` 识别（少数允许 UA 判断的场景）；版本按 L1 支持，单独测分享 / JSSDK。
- 华为浏览器（HarmonyOS 默认浏览器）为 B 级：核心功能可用即可。
- UC / QQ / 360 / 百度浏览器多为 Chromium 内核，按 Chrome 标准适配，抽样验证。

## 测试覆盖版本

- 「测试覆盖版本 = L1」：每个 A/B 级浏览器至少在最新的 1 个稳定版本上完成实测回归。
- 移动端部分浏览器（华为 / 360 / 百度）当前无固定测试覆盖，发布前抽样验证并记录版本。

## browserslist 配置建议

- A 级目标：`"last 3 versions"`（配合 `not dead`）。
- Safari 按 B 级：单独按 L2 收紧。
- 排除：`"not IE 11"`、`"not Edge < 79"`。
- 示例：

```json
{
  "browserslist": [
    "last 3 versions",
    "not dead",
    "not IE 11",
    "not Edge < 79"
  ]
}
```

- 用 `npx browserslist` 查看解析结果，autoprefixer / Babel preset-env 会按此目标自动生成前缀与转译。

## 版本数据来源

- 优先用产品自有统计（前端埋点采集浏览器版本分布）。
- 无统计时参考 StatCounter / 公司 IT 基线。
- 版本数据在每次产品版本上线前复核一次。
