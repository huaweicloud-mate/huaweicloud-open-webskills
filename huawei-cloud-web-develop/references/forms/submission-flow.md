# 提交流程、防刷与埋点

表单提交涉及状态管理、防重复提交、防刷与数据上报。以下为推荐实现与要点。

## 开工前对齐清单
- 与后端确认字段名映射、接口地址与响应结构。
- 与数据平台确认埋点事件前缀与上报 SDK（如百度统计、GA、dataLayer）。
- 默认约定：事件前缀 `form_`，字段名与接口字段一致，请求体为 JSON。

## 提交流程
1. 提交前执行全量校验，通过后进入提交中状态。
2. 提交中：按钮禁用并显示加载态（如「提交中…」），防止重复点击。
3. 提交成功：显示成功反馈（跳转、提示或弹窗），清空表单或按需求保留，触发成功埋点。
4. 提交失败：保留已填内容，区分业务错误与网络错误，网络错误提供「重试」。
5. 超时：前端 15 秒超时，提示「提交超时，请重试」，不自动重发。

## 防抖与节流
- 实时输入校验：用防抖（默认 300ms）聚合输入事件，避免每次按键都校验；模板已内置 `debounce`，用于「错误后实时重校验」。
- 提交按钮防连点：用按钮禁用 + 请求 token，不要用节流——节流会吞掉合法提交。
- 高频埋点（滚动、输入、曝光）：用节流或采样控制上报频率，避免打爆统计接口。

## 防重复提交
- 前端：提交中禁用按钮；会话内生成请求 token（如 crypto.randomUUID），提交时附带，成功后失效。
- 后端：对同一 token/会话做幂等控制，接口层限流（如每 IP/手机号 1 分钟内最多 N 次）。
- 原则：以服务端为准，前端只是体验兜底。

## 防刷与安全
- 蜜罐字段：表单中隐藏一个人类不会填写的字段（如 `website`），提交时该字段非空则静默丢弃，不提示不报错。
- 限流：按 IP、手机号、设备指纹限频；活动/报名类表单每人一次（手机号 + token 去重）。
- 校验码：高频或高风险表单加图形验证码或滑块验证。按风险分级配置：低风险（搜索、配置）基础限流即可；中风险（留资、数据录入）加校验码；高风险（登录/注册、活动报名）叠加手机号/设备维度限频与后台白名单。
- 服务端校验：所有字段重新校验，长度与白名单严格限制。
- 防注入：所有文本字段转义后入库，过滤 HTML/脚本字符。
- 密钥管理：前端不出现签名密钥、管理员凭据或未授权接口。

## 埋点与统计

事件统一命名（可按业务加前缀，默认前缀 `form_`）：

| 事件 | 触发时机 | 关键属性 |
| --- | --- | --- |
| form_view | 表单进入视口 | 页面来源、渠道 |
| form_start | 用户首次在表单内交互 | 渠道、字段数 |
| field_error | 字段校验失败 | 字段名、错误类型 |
| submit_click | 点击提交按钮 | 是否通过校验 |
| submit_success | 接口返回成功 | 提交耗时 |
| submit_fail | 接口返回失败或网络异常 | 错误码、错误信息 |

- 指标口径按场景约定：推广表单以提交成功为转化；注册/登录关注注册完成率、登录成功率与失败原因；数据录入关注录入完成率与放弃率；搜索关注搜索发起率与结果选择率。页面需透传渠道参数（如 utm_source）并随事件上报。
- 埋点参数避免包含手机号等敏感信息，确需上报时先脱敏。

## 接口约定与错误码
- 请求：POST，Content-Type 为 JSON 或表单编码（与后端确认）。
- 响应统一结构：`{ "code": 0, "message": "ok", "data": {...} }`，`code != 0` 视为业务失败。
- 错误码建议与后端对齐，前端按码映射提示，未识别的码走通用提示：

| 错误码 | 含义 | 前端提示 |
| --- | --- | --- |
| 40001 | 参数缺失或格式错误 | 「提交信息不完整，请检查后重试」 |
| 40002 | 业务校验失败（如已报名） | 「您已提交过报名信息」 |
| 40003 | 重复提交 | 「请勿重复提交」 |
| 40004 | 触发限流 | 「提交过于频繁，请稍后再试」 |
| 40005 | 验证码错误或失效 | 「验证码错误或已过期，请重新输入」 |
| 50000 | 服务异常 | 「服务暂时不可用，请稍后重试」 |
